Описание и заметки:
    Selenium webdriver - библа для управления браузерами и тестов, оттуда импортируем то что нам нужно.
    
    Структура:
     init.py - может быть пустой,  делает папку Python-пакетом, чтобы импортировать модули.
     BasePage (pages/base_page.py) - используем явное ожидание WebDriverWait, описаываем все общие методы, которые будем использовать, если что-то меняется, то правки вносим только сюда.
     MainPage (pages/main_page.py - описание главной страницу консоли.
     test_main.py (tests/test_main.py) - сценарии проверки.
     conftest.py (tests/conftest.py) - описание использование драйвера для браузера с указанием пути (сейчас это firefox).
     gitignore - чтобы не тащить всякий мусор лишний 
    
    POM (Page Object Model) - шаблон проектирования для автоматизации тестирования пользовательского интерфейса, создаем отдельный класс для страницы и там хранятся все локаторы элементов и методы для взаимодействия с ними, сосбна юзаем атрибут data-test-id="имя локатора" смотрится все это дело в консоли разработчика - иначе говоря классовые переменные в коде MainPage, чтобы дальше использоваться в методах.
    
    3 Уровня, на первом описание и локаторы, которые за тем используются в остальных двух уровнях, если что-то поменялось меняется только ту, нет дублирования кода, 2 уровень логика процессов, 1 уровень это тесты непосредственно.

    3 теста:
     test_console_title – проверяет заголовок 
     test_help_command – отправляет help и ждёт появления фразы BEHOLD!.
     test_unknown_command – отправляет несуществующую команду и проверяет, что появляется Unknown command

запуск тестов:

    python -m pytest tests/ --collect-only -v  #сбор тестов, покажет какие тесты найдены и их порядок, полезно, чтобы узнать видны ли вообще тесты.

    python -m pytest tests/ -v #запустит все тесты.

    python -m pytest tests/test_main.py::TestConsole::test_console_title -v #один конкретный

    python -m pytest tests/ -v --html=report.html #с отчетом

    python -m pytest tests/ -v --tb=short #с коротким выводом ошибок

    python -m pytest tests/ -v --pdb #режим отладки

По сути логика такая: запускаю pytest -> он находит все тесты в папке tests, для каждого теста создается отдельный бразуер, тест использует объект MainPage -> который наследует методы из BasePage -> открывается страница Selenium грузит URL -> затем с помощью явного ожидания находит элементы по data-test-id и взаимодействует с ними -> проверяет ожидаемый результат через assert (ключевое слово, которое првоеряет истинно ли условие) -> если все гуд, то зеленый PASSED/если нет, то красный FAILED -> затем браузер закрывается.
